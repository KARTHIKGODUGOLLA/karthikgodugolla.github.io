MaargAn SOP-controlled conversational AI agent for insurance claims

Deployed, try it

Insurance support follows a fixed process. Customers do not. So the LLM interprets each message into schema-validated fields, deterministic Python decides, and the LLM only phrases the reply.

  • Code owns identity verification, workflow phase and tool access. The model never decides any of them.
  • A deterministic guard inspects every reply for leaked personal data, invented amounts or dates, and false claims that an action happened. Failures regenerate, then fall back to a safe template.
  • 8-model fallback chain with a circuit breaker, transactional turns, and an inspector panel showing what the model understood versus what the workflow decided.
  • 53 automated tests covering verification rules, cross-customer isolation, consent, escalation and guard behavior.

Human vs AgentCan you tell a human from an AI agent by how the cursor moves, with no enrolment and no hardware attestation?

Research case study
0.999 AUCagainst my own adversaries
then
0.900 AUCagainst an independent attacker

30 features drawn from motor control literature, 13,605 human traces from 56 users, gradient boosting with GroupKFold split by user, and an automated leakage audit gating every result. Then I attacked it with a third-party library that predates the project: 79% of attacks passed (95% CI 67 to 88).

  • The diagnosis. One feature, the two-thirds power law correlation, was algebraically near-constant across generated traces (standard deviation 0.003), so it acted as a label. The model had learned how the negatives were manufactured, not how humans move.
  • Dataset bias, not model capacity. A motor-features-only probe still recovered the real signal (0.916 and 1.000 AUC), so the fix was to regenerate the negatives, not change the architecture.
  • Inference that ships. The whole feature pipeline hand-ported to zero-dependency JavaScript, client-side with no telemetry leaving the device, 0.7 ms per decision, numerical parity to 8.9e-15.
  • Also caught: sampling-rate leakage in step-based features, and a replay defence that let 87.5% of replays through, tightened to 8.2%.
