The problem

Insurance support follows a prescribed process, but customers do not talk in a prescribed order. Someone might give their name, describe a denied claim, get frustrated and ask a follow-up question all in one message. A free-form chatbot could disclose protected claim details before verifying identity, invent explanations, or act without consent. A rigid scripted bot forces people to repeat themselves and breaks on natural phrasing.

The approach: the LLM understands, code decides, the LLM phrases

Gemini converts each message into schema-validated structured fields (identity values with evidence spans, intent, claim hints, emotional state, requests for a human). A deterministic Python state machine then owns everything that matters: it validates the interpretation, updates memory, checks business rules and calls only permitted tools. The model never decides whether identity is verified, never sets the workflow phase and never invokes a protected tool directly. Workflow compliance is an application property, not a prompt instruction.

What that made possible

  • Identity verification requiring three distinct PII categories matching one customer record, with evidence-grounded extraction so hallucinated values cannot pass. It never reveals which field failed, supports corrections and withdrawals, and escalates to a human after repeated failures.
  • Memory across phases. Details mentioned before they are usable (for example "my denied healthcare claim from January") are stored and used later to find the right claim, without asking again and without disclosing anything early.
  • A deterministic output guard inspecting every generated reply for leaked personal data, invented dollar amounts, dates or claim IDs, and false claims that an action occurred. Failing replies regenerate with feedback, then fall back to a safe template.
  • Recovery and consent behavior: emotion detection with de-escalation, polite refusal of out-of-scope questions, a representative-authorization flow, and consent-gated email summaries where ambiguous consent is rejected.
  • Reliability: an 8-model fallback chain, a circuit breaker that pauses overloaded or quota-exhausted models, per-call time budgets, and transactional turns so a model outage never leaves the conversation half-updated.
  • Observability: a live inspector panel showing, per turn, what the model understood, what the workflow decided, and whether the reply passed the guard.

What is verified

53 automated tests passing, covering verification rules, cross-customer access isolation, consent, escalation, guard behavior, and malformed or refused model responses. Multi-stage Docker build, deployed on Render.

Honest framing: this is a production-style prototype. It is deployed and publicly reachable, and it does not serve real insurance customers. I am not claiming accuracy, cost savings or adoption numbers for it.

Why it matters. Most LLM demos fail because the model is trusted with decisions it should not make. This one is built the other way around.

Featured project

Human vs Agent, and what happened when I attacked my own model

Python scikit-learn pandas JavaScript Case study, no public repo yet

The problem

AI agents are beginning to transact on people's behalf. Every agentic commerce protocol has a step where a human is supposed to approve a purchase, and none of them verify that a human actually did. Signing a mandate proves a key was used, not that a person was present. The gap: a decision-scoped, portable, zero-enrolment signal of human presence, for cases where hardware attestation cannot be required.

The approach

Rather than ad hoc features, the feature set came from motor control literature: minimum-jerk velocity profiles (Flash and Hogan), ballistic and corrective submovements (Woodworth), path curvature under the two-thirds power law, Fitts's-law target acquisition, signal-dependent noise (Harris and Wolpert) and physiological tremor. Thirty features in seven groups, over 13,605 human traces segmented from 334 browser sessions across 56 users.

Validation was deliberately conservative: a gradient-boosted classifier with GroupKFold split by user, never randomly, because traces from one hand are not independent samples. An automated leakage audit (training on nuisance variables alone) gates every result. The decision threshold was set at 1% human false-reject rather than 0.5, because rejecting a real customer costs more than issuing one extra challenge.

Deployment

The full 30-feature extraction pipeline and a gradient-boosted-tree inference path were hand-ported to zero-dependency JavaScript, running client-side with no telemetry leaving the device: 0.7 ms per decision, numerical parity to 8.9e-15, exact model reproduction.

The turn

Against its own adversary suite the model scored 0.999 AUC. I did not believe it. Three independent attackers were built afterward specifically to test it honestly, including a third-party library written by someone else and predating the project, so there was no possibility of tuning against a known attack. Against that independent attacker, performance fell to 0.900 AUC, with 79% of attacks passing (95% CI 67 to 88).

The diagnosis

One feature, the two-thirds power law correlation, was near-constant across every generated trace for algebraic rather than behavioral reasons: on a straight line, curvature is inversely proportional to speed, so the correlation is approximately negative one by construction. Standard deviation across generated traces was 0.003. It had become a near-perfect label. The model had learned how the training negatives were manufactured, not how humans move.

A separability probe using motor features only confirmed the real signal was still recoverable (AUC 0.916 and 1.000 against two attacker profiles), which established the cause as dataset bias rather than model capacity or overfitting. That distinction determined the correct fix: regenerate the negatives, not change the architecture.

Methodology worth highlighting

  • Attacker and evaluator separation was designed and enforced. The attacker used to diagnose the model was permanently disqualified from evaluating it, because inspecting its traces and tuning against them is teaching to the test. Evaluation traces were programmatically excluded from analysis by default.
  • Wilson confidence intervals were reported throughout, and point estimates from n under 12 were refused.
  • Also found and fixed: a sampling-rate leakage defect where step-based features silently encoded the device polling rate, a replay-defence bug where replays passed 87.5% of the time (tightened to 8.2%), and contamination in my own attack harness, detected because one feature showed identical effect sizes for two structurally different attackers, which is a constant rather than a behavior.

Honest framing: this is a negative result, presented deliberately. The 0.999 AUC number only holds against self-generated adversaries and was contradicted by independent testing at 0.900.

Why it matters. The headline number was measuring an artifact of the data generator. Finding that was worth more than the number.
