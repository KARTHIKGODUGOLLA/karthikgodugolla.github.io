Research case study: Human vs Agent, and what happened when I attacked my own model

Python scikit-learn pandas JavaScript No public repo yet

Can you tell a human from an agent by how the cursor moves, with no enrolment and no hardware attestation? Thirty features drawn from motor control literature, 13,605 human traces from 56 users, gradient boosting with GroupKFold split by user, and an automated leakage audit gating every result.

  • Against my own adversary suite the model scored 0.999 AUC. Against an independent third-party attacker that predates the project, it fell to 0.900 AUC, with 79% of attacks passing (95% CI 67 to 88).
  • Cause: one feature, the two-thirds power law correlation, was algebraically near-constant across generated traces (standard deviation 0.003), so it acted as a label. The model had learned how the negatives were manufactured, not how humans move.
  • A motor-features-only probe still recovered the real signal (0.916 and 1.000 AUC), which pinned the problem on dataset bias rather than model capacity. The fix was to regenerate the negatives, not change the architecture.
  • Engineering side: the 30-feature pipeline and tree inference were hand-ported to zero-dependency JavaScript, client-side with no telemetry, 0.7 ms per decision, numerical parity to 8.9e-15.

A negative result, on purpose. The 0.999 figure only holds against self-generated adversaries, and independent testing contradicted it.

Why it matters. The headline number was measuring an artifact of the data generator. Finding that was worth more than the number.

Engineering

Maarg, an SOP-controlled conversational AI agent for insurance claims

Python FastAPI Gemini React and TypeScript Docker pytest

Insurance support follows a fixed process. Customers do not. Maarg splits the work: the LLM interprets each message into schema-validated fields, deterministic Python decides, and the LLM only phrases the reply.

  • Code owns identity verification (three distinct PII categories, evidence-grounded so hallucinated values cannot pass), workflow phase and tool access. The model never decides any of them.
  • A deterministic output guard checks every reply for leaked personal data, invented amounts, dates or claim IDs, and false claims that an action happened. Failures regenerate, then fall back to a safe template.
  • 8-model fallback chain with a circuit breaker, transactional turns, and an inspector panel showing per turn what the model understood and what the workflow decided.
  • 53 automated tests cover verification, cross-customer isolation, consent, escalation and guard behavior. Multi-stage Docker build, deployed on Render.
